# ギジログ

ビデオ会議を録音しながら、議事録をその場で書き上げていく macOS アプリです。
会議中は小さな画面を会議の横に置き、決まったこと・残っている論点・担当を確かめながら進行できます。

## できること

- **録音**：Zoom・Teams・Google Meet などに参加したまま、Mac から出る音とマイクの声を別々のトラックで録音します。会議アプリの設定は変えず、画面の録画の許可も要りません。
- **リアルタイムの議事録**：話の切れ目（10〜25秒ごと）で区切って OpenAI で文字起こしし、30秒ごとに議事録を書き足します。声のない区間は送らず、会議名・アジェンダ・用語集・直前の発言をヒントに渡すので、固有名詞や文のつながりが崩れにくくなっています。
- **進行しやすい小画面**：決定事項・未決事項・アクションアイテムを並べ、直近の更新で変わった項目に色を付けます。担当や期限が決まっていないアクションは目立たせるので、その場で確認できます。議事録・文字起こし・アジェンダはタブで切り替えます。
- **根拠のある議事録**：議事録の各項目には、もとになった発言の時刻が付きます。発言に根拠のない項目や、発言にない担当者・期限は載せません。
- **録音ファイルからも作成**：ボイスメモや Zoom の録画など、あとから音声・動画ファイルを読み込んで議事録にできます。
- **音声と議事録をまとめて保存**：会議ごとのフォルダに `議事録.md` と `録音.m4a` を残します。
- **タグで探せる**：会議にタグを付けて、一覧をタグで絞り込めます。
- **アジェンダ**：会議の前に議題を用意しておくと、会議中はどの議題を話しているかを AI が文字起こしから判断し、今の議題と経過時間を表示します。議題ごとにかかった時間が議事録に残ります。
- **キーワード検索**：タイトル・タグ・議事録・文字起こしをまとめて検索し、一致した箇所に色を付けます。
- **議事録と文字起こしを直せる**：項目や発言をクリックして直せます。聞き間違えた名前を直すと、同じ語や読みが同じ別の表記（森バス・もりばす→モリバス）を会議全体からまとめて直せます。
- **会議について質問できる**：一覧の上の「ギジログAI」を押して「先週決まったことは？」「中塩さんの終わっていないアクションは？」のように聞くと、AI がすべての会議から探して答えます。答えのリンクから、その会議と発言を開けます。
- **AI アプリから使える（MCP）**：Claude Code や Claude Desktop などから「先週の定例で決まったことは？」「未完了のアクションは？」と聞けます。通信はこの Mac の中だけです。

## 必要なもの

- macOS 15 以降
- OpenAI の API キー（利用料は各自の負担です）
- ビルドする場合：Swift 6 以降（Xcode または Command Line Tools）と [SwiftLint](https://github.com/realm/SwiftLint)

## はじめかた

```sh
brew install swiftlint
git clone https://github.com/nutcase/gijilog.git
cd gijilog
./scripts/build.sh
open dist/ギジログ.app
```

1. 設定（⌘,）で OpenAI の API キーを保存します。
2. ツールバーの「新規録音」を押すと、新しい会議として録音と議事録づくりが始まります。初回は macOS がマイクとシステムオーディオ（Mac から出る音）の録音の許可を求めるので、どちらも許可してください。画面の録画の許可は要りません。
3. 会議のタイトルは録音の日時で始まります。議事録の見出しのタイトルをクリックすると変えられます（Enter で確定、Esc で元に戻す）。

録音の始め方は、どこから押すかで決まります。

| 場所 | ボタン | 押すと |
| --- | --- | --- |
| ツールバー右上 | 新規録音（⌘⇧R） | いつでも新しい会議を録音します |
| 準備中の会議のページ | この会議を録音 | その会議の録音を始めます |
| 終わった会議のページ | 続けて録音 | その会議の続きを録音します |
| 一覧の「会議」の見出しの ＋ | アジェンダを準備（⌘N） | 録音前の会議を作ります |

「続けて録音」は、休憩をはさんだ会議などを同じ議事録にまとめるときに使います（「この会議」メニューにもあります）。時刻は前の録音の終わりから続き、文字起こしと議事録は後ろに書き足されます。止めると録音.m4a は前後をつないで 1 つになり、議事録は全体をもう一度仕上げます。

録音の開始と停止は、画面右上のメニューバーのアイコン（波形、録音中は録音マーク）や、アプリの「録音」メニュー（⌘⇧R）からもできます。ウインドウを閉じていても使えます。

| ショートカット | 内容 |
| --- | --- |
| ⌘⇧R | 新規録音・録音の停止 |
| ⌘N | アジェンダを準備（録音前の会議を作る） |
| ⌘O | 録音ファイルを読み込む |
| ⌘F | 会議を検索 |
| ⌥⌘F / ⇧⌘F | 開いている会議の議事録／文字起こしの中を検索 |
| ⌘1 / ⌘2 / ⌘3 | 小画面の「議事録」「文字起こし」「アジェンダ」タブ |
| ⌘, | 設定 |

> [!NOTE]
> 開発用の署名（ad-hoc）でビルドすると、ビルドし直すたびに録音の許可が外れ、保存した API キーを読むときにキーチェーンの確認も出ます（「常に許可」を押してください）。録音の許可が外れたときは次のコマンドで古い許可を消し、2. からやり直してください。固定の署名で避ける方法は「[ビルドし直しても許可を保つ](#ビルドし直しても許可を保つ)」にあります。
>
> ```sh
> tccutil reset AudioCapture io.github.nutcase.gijilog
> ```
>
> 許可はあとから、システム設定の「プライバシーとセキュリティ」→「画面とシステムオーディオの録音」→「システムオーディオ録音のみ」で切り替えられます。Mac 音声の波形が平らなままなら、ここを確認してください。

## 使い方

### 会議中は小画面で

録音を始めると小画面に切り替わり、ほかのウインドウより手前に表示されます。

- 上部：経過時間、Mac 音声とマイクの音量の波形、停止ボタン。マイクの波形が平らなままなら、声が入っていません。
- アジェンダがある会議では、その下に今の議題（何番目か・経過時間・予定時間）が出ます。予定時間を過ぎると色が変わります。
- 「議事録」タブ：要約 → 決定事項と理由 → 未決事項・次の確認 → 議論の経緯 → アクションアイテムの順に並び、下端に最新の発言が出ます。要約は紫の番号、決定事項は緑、未決事項は山吹色、アクションアイテムは青の印で見分けられます。欄の見出しをクリックすると、その欄を畳んだり開いたりできます。畳んだ欄は次に開くまでどの会議でも畳んだままで、議事録の中の検索で見つかった項目があるときだけ開きます（どちらも大きい画面も同じ）。
- 「文字起こし」タブ：文字起こし全体。録音中は最新の発言まで自動でスクロールし、読み返している間は止まります。
- 「アジェンダ」タブ（アジェンダがある会議だけ）：議題ごとの進み具合とかかった時間。
- ピンで手前への固定を外せます。矢印のボタンで大きい画面に戻ります。画面を切り替えても録音は続きます。
- 会議が終わったのに録音を止め忘れても、マイクにも Mac 音声にも声や物音がない状態が15分続くと、録音を自動で止めます。止める1分前に「あと◯秒で録音を止めます」と出るので、「録音を続ける」で続けられます。空調などの一定の音は無音として扱います。止めたときは会議のページにその旨が出るので、続きがあれば「続けて録音」で録れます。時間は設定の「一般」で 5〜60分か「しない」に変えられます。

### 会議のあとは大きい画面で

左に会議の一覧（検索欄とタグの絞り込み付き）、中央に議事録、右に文字起こしを並べて表示します。アジェンダがある会議では、議事録の先頭にアジェンダが出ます。録音中の文字起こしは最新の発言まで自動でスクロールし、読み返している間は止まります。

ツールバーからできること：

| ボタン | 内容 |
| --- | --- |
| 読み込み | 録音ファイル（音声・動画）を選んで議事録を作る（⌘O） |
| 書き出し | 議事録を Markdown で好きな場所に保存。文字起こしも入れるときは、横の矢印から「文字起こしも含めて書き出す…」 |
| この会議 | 議事録を仕上げる、未処理を再開、全文を再処理、Finder で表示、ゴミ箱に移動 |
| 小画面にする | 小画面に切り替え |
| 文字起こし | 右側の文字起こしの表示を切り替え |

通信が一時的に途切れた場合（タイムアウト、接続断、TLS・名前解決のエラーなど）は、文字起こしを約1分のあいだ自動で再試行します。それでも失敗すると、大きい画面と小画面の両方に原因と「再試行」ボタンが出ます。録音中でも、失敗した部分だけをやり直せます。

### アジェンダを準備する

- 一覧の「会議」の見出しにある ＋（アジェンダを準備、⌘N でも）で、録音前の会議を作ります。一覧には「準備中」と表示されます。
- 議題を入力して Enter で追加します。カレンダーの招待文やチャットの箇条書きを貼り付けると、1行ずつ議題になります。「・」「1.」などの記号は外し、「（10分）」「15 min」のような末尾の時間は予定時間として読み取ります。
- 議題をクリックすると、名前・決めたいこと・予定時間を編集できます。「…」から並べ替えと削除ができます。
- 会議の時間になったら、準備した会議のページの「この会議を録音」を押します。
- どの議題を話しているかは、約30秒ごとの議事録の更新のときに AI が文字起こしから判断します（追加の API 呼び出しはありません）。手で切り替える必要はありません。議題は、その話が始まった発言の時刻で区切ります。
- 一度終えた議題に戻った場合も、話していた時間を合計します。予定時間を過ぎると経過時間の色が変わります。録音を止めると、進行中の議題もそこで終わります。`議事録.md` にはアジェンダと議題ごとの予定・実際の時間が残ります。録音前の会議の `議事録.md` は、共有用のアジェンダになります。
- アジェンダは任意です。用意しなくても、これまでどおり「新規録音」で録音できます。

### タグで整理する

- 議事録のタイトルの下にある「タグを追加」から付けます。入力して Enter で追加し、カンマ（、）で区切るとまとめて追加できます。これまでに使ったタグは候補から選べます。
- 一覧で会議を右クリックして「タグ」からも付け外しできます。
- 一覧の「会議」の見出しにある絞り込みのボタンを押すとタグが並び、押したタグが付いた会議だけを表示します。複数選ぶと、すべてのタグが付いた会議に絞り込みます。選んだタグは検索欄の下に並び、× を押すとそのタグでの絞り込みをやめます。「解除」で全件に戻ります。
- 設定の「タグ」（タグの絞り込みの「管理」からも開けます）で、タグの名前を変えたり削除したりできます。名前の変更はそのタグが付いたすべての会議に反映され、ほかのタグと同じ名前にするとひとつにまとまります。削除しても会議は消えません。
- 大文字と小文字、全角と半角の違いは同じタグとして扱います。タグは `議事録.md` のタイトルの下にも書き出します。
- 録音を始めたりファイルを読み込んだりすると、新しい会議が見えるように絞り込みを解除します。

### キーワードで探す

- 一覧の上の検索欄（⌘F）に入力すると、タイトル・タグ・議事録・文字起こしのどこかに一致する会議だけを表示します。会議ごとに、一致した箇所の抜粋も出ます。
- スペースで区切ると、すべてのキーワードを含む会議に絞り込みます。大文字と小文字、全角と半角は区別しません。タグの絞り込みとも組み合わせられます。
- 会議を開くと、議事録と文字起こしの一致箇所に色が付き、文字起こしは最初の一致箇所までスクロールします。
- 開いている会議の中は、議事録（日付の行の 🔍 か ⌥⌘F）と文字起こし（見出しの 🔍 か ⇧⌘F）を別々に検索できます。一致した項目・発言の数と今の位置（3/12 など）が出て、Return か ↓ で次、↑ で前の一致へ移ります。Esc で閉じます。

### ギジログAI に質問する

<p align="center">
  <img src="docs/images/ask.jpg" alt="ギジログAI（すべての会議、またはタグで絞った会議について質問し、答えのリンクから会議と発言を開く）" width="720">
</p>

- 大きい画面の左上、アプリ名の下にある「ギジログAI」を押すと、真ん中が会話の画面になります。聞きたいことを入力して Return を押します。「この会議の要点は？」と聞くと、直前まで開いていた会議について答えます。
- 質問欄の上の「対象」でタグを選ぶと、選んだタグのどれかが付いた会議だけから答えます（「QB」と「prd」を選べば、どちらかの付いた会議）。選んだタグは × で外せ、外しきるとすべての会議に戻ります。
- AI は対象の会議の議事録と文字起こしから、必要なものを探して読み、答えます。いま何を読んでいるか（「「QB」で会議を探しています」など）が表示され、「止める」で途中でやめられます。
- 答えには、根拠になった会議と発言へのリンクが付きます。押すとその会議を開き、文字起こしの該当する発言に枠を付けてスクロールします。会話に戻るときは、もう一度「ギジログAI」を押します。
- 続けて聞くと、直前の5往復の質問と答えを踏まえて答えます。「新しい会話」で最初からにできます。会話はアプリを終了すると消えます。
- 読むだけで、議事録や会議は変えません。モデルは設定の「議事録のモデル」を使います。AI アプリ（MCP）向けの設定で除いた会議や文字起こしも、このタブでは対象になります。

### AI アプリから使う（MCP）

Claude Code・Claude Desktop など MCP に対応した AI アプリから、ギジログの会議を読み取れます。

1. 設定の「AI 連携」で「Claude Code に追加」または「Claude Desktop に追加」を押します（最初の一度だけ）。
   - Claude Code：`claude mcp add` で登録します。claude コマンドが見つからなければ、コマンドをコピーします。
   - Claude Desktop：拡張機能（`ギジログ.mcpb`）を開くので、Claude Desktop の画面で「インストール」を押します。
   - ほかの AI アプリには、表示されているコマンド（`ギジログ.app/Contents/MacOS/gijilog-mcp`）を MCP サーバーとして登録します。「ほかの AI アプリ用の設定（JSON）をコピー」も使えます。
2. あとは AI アプリに聞くだけです。ギジログが起動していなければ自動で起動し、途中で終了しても次の質問でつなぎ直します。

Claude Desktop に追加した拡張機能は、Claude デスクトップアプリの Code タブ（Claude Code）でもそのまま使えます。登録を外すときは、Claude Desktop では設定の「拡張機能」から削除し、Claude Code では `claude mcp remove --scope user gijilog` を実行します。

| ツール | 内容 |
| --- | --- |
| `list_meetings` | 会議の一覧（期間・タグで絞り込み） |
| `search_meetings` | キーワード検索。一致した箇所（議事録の項目・アジェンダ・文字起こしの発言と時刻）を会議ごとに返す。スペース区切りはすべて含む会議だけ |
| `get_meeting` | 議事録（決定と理由、未決と次の確認、アクション、アジェンダ） |
| `get_transcript` | 文字起こし（時刻の範囲を指定、長い会議は分けて返す） |
| `list_action_items` | 会議をまたいだアクションアイテム（未完了・担当者で絞り込み） |
| `get_current_meeting` | 録音中の会議の、今の議題と最新の議事録 |
| `list_tags` | タグと件数 |

- ツールは読み取りだけです。会議の削除や録音の開始・停止はできません。
- 通信はこの Mac の中だけです。ギジログは本人だけが開ける Unix ソケット（`~/Library/Application Support/Gijilog/mcp.sock`）で待ち受け、ネットワークのポートは開きません。
- AI アプリに渡した内容は、そのアプリの提供元（Anthropic など）に送られます。「文字起こしも渡す」をオフにすると議事録とアジェンダだけを渡し、タグを指定するとその会議は AI アプリから見えなくなります。
- 設定の「最近のアクセス」に、どの AI アプリがどのツールを使ったかが出ます。
- 機能ごと止めるには「AI アプリから会議を読めるようにする」をオフにします。

### 決まったことと次の行動が分かる議事録

- 決定事項には、発言にある判断理由を添えます。提案や検討中の案は決定と区別します。
- 未決事項には、決めるために必要と話された「次の確認」を添えます。
- 要約は話題ごとに、話された順に番号を付けて、概要（何を話し、どうなったか）・主な論点・主な意見を書きます。論点と意見は1つの話題に3つまでで、発言者は書きません。結論は決定事項の欄に書き、要約では繰り返しません。決定事項・未決事項・アクションアイテムは、出てきた話題ごとに要約と同じ番号の見出しの下にまとめ、どの話題にも入らないものは「その他」に入れます（`議事録.md` も同じ）。これらの文は、それだけ読んで何の件か分かるように書かせています。以前の議事録も、根拠の発言の時刻から話題を推定してまとめます。「〜との発言があった」のような言い回しや、話されなかったことは書きません。論点と意見も、項目をクリックして1行に1つずつ直せます。
- 担当・期限の根拠がないアクションアイテムは「未定」と表示します。
- 各項目の「根拠」を開くと、発言時刻と原文を確認できます。
- 録音中の議事録では、方針が変わった経緯や撤回済みの案も確認できます（「議論の経緯」）。
- `議事録.md` は 要約 → 決定事項と理由 → アクションアイテム → 未決事項 → 文字起こし の順で、時刻は「40:24」のように書きます。

録音中は30秒ごとの更新を続けます。停止後、残りの文字起こしが終わったら、文字起こし全体と会議中の議事録を AI に一度に渡して、議事録を通して書き直します（約4時間を超える会議は分けて仕上げ、成功したところまで保存します）。終了や通信失敗の後も「未処理を再開」で続けられます。仕上げには追加のAPI利用料と時間がかかります。

以前の会議にも「この会議 → 議事録を仕上げる」を使えます。保存済みの文字起こしだけを使い、音声の再送・再認識はしません。以前の完了済み会議を起動時に自動で仕上げ直すことはありません。担当・期限は原文との照合、根拠IDは存在と時刻の検証を行いますが、理由や結論の意味が正しいかはAIの判断を含むため、重要な内容は根拠発言を確認してください。

### 議事録を直す

会議が終わった議事録は、大きい画面で直せます（録音中や議事録の更新中は直せません）。

- 項目をクリックすると、その場で編集できます（マウスを乗せると鉛筆の印が出ます）。Return で確定、Esc で取り消し。アクションはチェックボックスで完了にできます。担当の札をクリックすると、これまでの会議で担当者になった人が並び、押すだけで加わります（もう一度押すと外れ、新しい名前も入力できます）。担当者は複数にでき、AI も発言に出てきた担当者を全員書きます。期限の札をクリックするとカレンダーが開き、日付を選べます。「金曜」「10月10日」のように話された期限は、会議の日から数えた日付として表示されます。項目を右クリックすると削除、各節の「＋ 追加」で項目を足せます。
- 決定事項・未決事項・アクションアイテムは、文を直して別の話題の名前を入れると、その話題の下へ移ります（もとの話題の名前を残したままなら移りません）。項目を別の話題の見出しや項目の上へドラッグするか、右クリックの「話題を移す」から選んで移すこともできます。
- 手で直した項目には「手直し」と表示され、そのあと「議事録を仕上げる」や「全文を再処理」をしても AI は書き換えません。削除した項目も AI が書き戻しません。
- 右側の文字起こしも、発言をクリックすると直せます（録音中も直せます）。右クリックで発言を削除でき、雑音から作られた意味のない行を消せます。手で直した発言には鉛筆の印が付きます。
- 会議が終わったあとに発言を直したり消したりすると、その発言をもとにした議事録の項目に「要確認」の印が付き、議事録の上にお知らせが出ます。「訂正を反映して更新」で直した文字起こしから議事録を作り直し（手で直した項目はそのまま）、「このままにする」で印を消します。語句の一括修正は議事録も同時に直すので、印は付きません。
- 録音が終わった会議では、根拠の発言と右側の文字起こしの行（マウスを乗せたとき）に ▶ が出て、その発言を録音（録音.m4a）で聞き返せます。その発言の始まりから次の発言の手前まで、長くても30秒鳴らします。続けて録音した会議でも、発言の時刻がそのまま録音の位置です。
- 項目や発言の中の語を直すと、同じ語がほかにもあれば「ほかの N か所も直しますか？」と聞きます。「この会議 → 語句をまとめて直す…」からも直せます。
- 同じ表記に加えて、読みが同じ別の表記（森バス・もりばす→モリバス）も候補に出します。読みは Mac の中で調べ、外部には送りません。候補ごとに前後の文を見て、直す箇所を選べます。
- 直した語は会議ごとに覚えておき、録音中ならその後の文字起こし、仕上げや再処理のあとの議事録にも同じ直しを当てます。正しい語は文字起こしのヒントにも入れます。「用語集にも追加」を選ぶと、ほかの会議でも使います。
- 直した語は「森バス、もりばす → モリバス」のように聞き間違いとしても覚え、これからのすべての会議で、同じ聞き間違いを自動で直し、正しい語を文字起こしのヒントに使います。議事録を取るほど、そのチームの言葉に強くなります。自動で直した語は「語句をまとめて直す…」に「自動」と出て、その会議だけ取り消せます。この機能が入る前に直した語も、最初の起動で覚えます。覚えた聞き間違いは設定の「文字起こし」で見たり消したりでき、用語集と一緒に保存先の `vocabulary.json` に保存するので、保存先を同期していればほかの Mac とも共有されます。
- 担当者になった人の名前も、文字起こしのヒントに使います。
- 直した語は「語句をまとめて直す…」の一覧から取り消せます。

### 録音ファイルから作る

ツールバーの「読み込み」（⌘O）で音声・動画ファイルを選ぶか、ファイルをウインドウにドロップします。複数のファイルをまとめて選ぶこともできます。

- 録音中と同じく、話の切れ目で区切って文字起こしし、終わったら議事録を作ります。音声トラックが複数ある動画は、すべてのトラックを重ねて読み込みます。
- 録音中でも読み込めます。読み込み中も、録音はいつでも止められます。
- タイトルはファイル名、日時はファイルの作成日時になります。
- 会議フォルダに `議事録.md` と `録音.m4a` を作ります。元のファイルはそのまま残ります。

### 保存されるもの

保存先は、既定では書類フォルダの `ギジログ` です。設定で変更でき、変更するとこれまでの会議も移動します。

アプリを起動している間に保存先へ会議のフォルダが加わると（別の Mac から iCloud Drive などで同期された、バックアップから戻した、ゴミ箱から戻した など）、再起動しなくても一覧に出ます。同期の途中で中身がそろっていないフォルダは、そろった時点で出ます。すでに一覧にある会議の写し（名前に「(2)」が付いたものなど）は出しません。一覧にある会議がほかの Mac で直されて同期されてきたときも、起動中のまま読み込み直します。ただし、この Mac で録音中・処理中・編集中の会議や、まだ保存していない直しがある会議は、この Mac の内容を優先し、次の保存で上書きします。読み込んだ会議の文字起こしや議事録の作成はこの Mac では始めないので、2台で同じ会議を同時に編集しないでください。

用語集と覚えた聞き間違いは、保存先の `vocabulary.json` にまとめて置くので、保存先を同期していれば会議と一緒に共有されます。ほかの Mac で書き換えられると、起動中でも読み込み直します。`terms` が用語集、`corrections` が覚えた聞き間違い（`heard` が聞き間違えた表記、`correct` が正しい表記）で、1行に1つずつ並べるので、手で書き換えることもできます。保存と自動の直しが重くならないよう、用語集は100語まで（超えた分は保存せず、使いません）、覚えた聞き間違いは100件まで（超えると、いちばん長く直していないものから忘れます。1件に覚える聞き間違えた表記は10通りまで）です。書き方に誤りがあって読み込めないときは、設定の「文字起こし」に何行目あたりかを出し、直すまでアプリからは上書きしません。以前の版の `語句リスト.txt` と `聞き間違い.txt`、設定に入れていた用語集は、起動したときにこのファイルへ移します（ファイルがすでにあれば、両方の語を合わせます）。

```json
{
  "terms": [
    "ギジログ",
    "山田 花子"
  ],
  "corrections": [
    { "heard": ["森バス", "もりばす"], "correct": "モリバス" }
  ]
}
```

```text
~/Documents/ギジログ/
├── vocabulary.json      用語集と覚えた聞き間違い（すべての会議で共通）
└── 2026-10-03 17.26 週次定例/
    ├── 議事録.md        議事録と文字起こし（更新のたびに書き直します）
    ├── 録音.m4a         Mac 音声とマイクを重ねた聞き返し用の音声（録音の停止後に作成）
    ├── chunks/          作業用の音声（文字起こしのために話の切れ目で区切った音声）
    ├── recording.json   ここから下はアプリが使うデータ
    └── meeting.json     タグ・アジェンダを含む会議の情報
```

`議事録.md` はアプリが書き直すので、手を加えるときは別名で保存してください。アジェンダを準備しただけの会議のフォルダには、`meeting.json` とアジェンダの `議事録.md` だけがあります。

### 容量

- 録音中と処理中は、作業用の音声（`chunks/`）が1時間あたり約230MB を使います。
- 議事録まで完了して `録音.m4a` ができると、作業用の音声は自動で削除されます。残るのは1時間あたり約10MBの `録音.m4a` と議事録だけです。自動削除は設定で切り替えられます。
- 設定の「保存先」で使用量の内訳を確認でき、「作業用の音声を整理…」で、完了した過去の会議の分もまとめて削除できます。
- 作業用の音声がない会議を「全文を再処理」すると、`録音.m4a` から文字起こしし直します。このとき Mac 音声とマイクは区別されません。文字起こしに失敗した会議は、再試行できるよう作業用の音声を残します。

### 設定

| 項目 | 内容 |
| --- | --- |
| API キー | OpenAI の API キー。Mac の Keychain に保存します |
| 議事録のモデル | 議事録を作るモデル（初期値 `gpt-6-sol`）。文字起こしは `gpt-transcribe` です |
| マイク | 録音するマイク。会議の音はイヤホンで聞き、声は Mac 本体のマイクで録るのがおすすめです |
| 音がないときの自動停止 | 声や物音がない状態がこの時間続くと録音を止めます（既定 15分、しない も選べます） |
| 保存先 | 会議フォルダを置く場所と使用量。完了した会議の作業用の音声を自動で削除するか、過去の分を整理するかもここで選びます |
| 文字起こし（別タブ） | 用語集と、直した語から覚えた聞き間違い（どちらも保存先の `vocabulary.json`）。どちらも文字起こしで使います |
| タグ（別タブ） | タグごとの会議の件数、名前の変更・統合、削除 |
| AI 連携（別タブ） | MCP のオン・オフ、文字起こしを渡すか、渡さないタグ、AI アプリへの登録、最近のアクセス |

## プライバシーと録音の同意

- **OpenAI に送るもの**：話の切れ目で区切った音声（声のない区間は送りません）、文字起こしのヒント（会議のタイトル、アジェンダの議題、用語集、直前の発言）、文字起こしの文章、それまでの議事録、録音中はアジェンダ（議題と決めたいこと）。「ギジログAI」では、質問とそれまでの会話、AI が読んだ会議の議事録・文字起こし・タグ。議事録の生成と質問は `store: false` で依頼します。
- **Mac に残るもの**：録音、文字起こし、議事録、アジェンダ、タグ。API キーは Keychain にあり、会議のファイルには書き込みません。
- **AI アプリ（MCP）に渡すもの**：AI アプリがツールで求めた会議の議事録・アジェンダ・文字起こし（設定で文字起こしや特定のタグの会議を除けます）。渡した内容は、その AI アプリの提供元に送られます。
- **同意**：会議を録音・文字起こしするときは、参加者に伝えて同意を得てください。録音に関する法令や所属先の規程にも従ってください。
- **確認**：議事録は AI による要約です。大事な内容は文字起こしの原文で確かめてください。

書類フォルダを iCloud Drive と同期している場合は、録音もアップロードされます。

## 制限

- 話者は区別しません。「Mac 音声」「マイク」は音が入ってきた経路です。
- スピーカーで会議の音を流すとマイクにも入り、二重に録音されます。イヤホンを使ってください。
- 30秒は更新の間隔の目安です。通信や API が遅いと遅れます。
- どの議題を話しているかの判断は、この更新に合わせて行うため、話題が変わってから表示が変わるまで30秒ほどかかります。AI の判断なので、ずれることもあります。
- 長い会議では、それまでの議事録も毎回送るため、モデルの入力上限に近づくことがあります。
- 配布用の署名と公証には対応していません。ソースからビルドして使ってください。

## 開発

```sh
./scripts/check.sh   # 整形チェック → SwiftLint → 回帰テスト → リリースビルド
./scripts/format.sh  # Swift コードを整形
./scripts/test.sh    # 回帰テストだけ
./scripts/build.sh   # チェックに通ったら dist/ギジログ.app を作る
```

- 整形は [swift-format](https://github.com/swiftlang/swift-format)（`.swift-format`）、静的チェックは SwiftLint（`.swiftlint.yml`）で、警告もエラーとして扱います。
- 回帰テスト（87件）は、続けて録音したときの時刻と音声のつなぎ、無音が続いたときの自動停止、録音の分割（話の切れ目での区切り）と時刻合わせ、声のない区間の判定と文字起こしのヒント、議事録の手直しと語句の一括修正、直した語の学習と自動の直し、担当者と期限の選び方、発言の聞き返し、要約の話題ごとの論点と意見、アクションの話題ごとのまとめ、議事録の差分更新と根拠の検証、再試行と再起動からの復旧、保存先の移動と以前の版からの引き継ぎ、起動中に保存先へ加わった会議や更新された会議の読み込み、録音ファイルの合成と読み込み、作業用の音声の削除と録音.m4a からの再処理、議事録の仕上げ、タグの表記ゆれ・絞り込み・名前の変更と削除、キーワード検索、アジェンダの読み取りと AI による議題の追跡、MCP の新旧両方式への応答・キーワード検索・渡さない設定・ソケット経由の往復などを確かめます。音声認識と API は模擬応答で、模擬していない通信はテスト中すべて失敗させます。
- GitHub Actions で、push と Pull Request ごとに SwiftLint・回帰テスト・リリースビルドを実行します。
- アイコンは Icon Composer 形式の `Resources/AppIcon.icon` です。Xcode があれば `build.sh` が actool で組み込み、macOS 26 以降はどのサイズもこの形式で描かれます。Xcode がなくても、`Resources/AppIcon.png`（と 16・32px 用の絵）から作る icns でビルドできます。
- Command Line Tools だけの環境では、SwiftUI の `@State` がコンパイルできません。画面の状態は `ObservableObject` に持たせています。

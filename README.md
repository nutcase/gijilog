# キロクル

macOS 15以降向けのSwiftUIアプリ。ビデオ会議に参加しながらMacの出力音声とマイクを録音し、OpenAIで文字起こしと議事録づくりをリアルタイムに進めます。会議中は小さな「ライブ議事録」ウインドウを会議画面の横に置き、決まったこと・残っている論点・担当を確かめながら進行できます。

## 起動

開発時はSwift 6以降のCommand Line Tools（またはXcode）とSwiftLintが必要です。SwiftLintは初回にインストールしてください。

```sh
brew install swiftlint
```

```sh
./scripts/build.sh
open dist/キロクル.app
```

`build.sh` は整形チェック・静的チェック・回帰テストに成功してから、リリースビルドとアプリの作成を行います。

初回は「画面とシステムオーディオの録音」とマイクの許可が必要です。録音を初めて開始すると許可を求められるので、システム設定で「キロクル」をオンにしてアプリを開き直してください。

**ビルドし直すと録音の許可が外れます。** アプリは既定でad-hoc署名のため、ビルドのたびに署名が変わり、macOSが以前の許可を使わなくなります。そのたびに許可し直すか、次のように固定の署名証明書を使ってください。

1. キーチェーンアクセスの「証明書アシスタント」→「証明書を作成」で、名前（例：キロクル開発）、種類「自己署名ルート」、証明書のタイプ「コード署名」の証明書を作る。
2. `KIROKURU_SIGN_IDENTITY="キロクル開発" ./scripts/build.sh` でビルドする。

許可が古い署名のまま残って一覧で切り替えられない場合は、`tccutil reset ScreenCapture local.minutes.kirokuru` で消してから録音を開始し直してください。

## 使い方

1. 設定でOpenAIのAPIキーを保存します（Keychainに保存）。議事録のモデル（初期値 `gpt-6-sol`）とマイクも選べます。設定は「保存」を押すまで反映しません。選んだマイクが接続されていない場合は録音を開始しません。
2. 会議が始まったら、タイトルを入れて（空欄なら日時）「録音を開始」を押します（⌘⇧R）。音声ルーティングや会議アプリのマイク設定は変更しません。
3. 録音を始めると小画面に切り替わり、大きい画面は閉じます。小画面はほかのウインドウより手前に表示されます（ピンで固定を解除できます）。小画面の「元の画面に戻す」ボタンで大きい画面に戻ります。録音中でも切り替えられ、画面を閉じても録音は続きます。内容は「決定事項・未決事項・アクションアイテム・要約」の順で、直近の更新で加わった・変わった項目に色を付けます。担当や期限が未定のアクションは件数と項目に印を付けます。下端には最新の発言を表示します。上部の波形で、Mac音声とマイクにそれぞれ音が入っているかを確認できます。
4. 約12秒ごとの音声をOpenAIで文字起こしし、30秒ごとに既存の議事録と新しい発言から差分更新します。前の要約が処理中なら更新要求をまとめ、完了後に最新の発言を反映します。要約に失敗した場合は画面に表示し、録音中は30秒から最大5分まで間隔を広げながら自動で再試行します。停止時にも1回再試行します。
5. 大きい画面では、議事録を用紙のように表示し、右側に文字起こしを並べます（ツールバーで表示を切り替え、「小画面にする」で小画面へ）。録音中の文字起こしは最新の発言まで自動でスクロールし、読み返すためにさかのぼると止まって「最新の発言へ」ボタンが出ます。停止すると音声ファイルを閉じ、残りはバックグラウンドで処理します。すぐに次の会議の録音を開始できます。
6. 失敗した会議は、表示される「未処理を再開」で未完了の音声だけ再実行できます。ツールバーの「この会議」メニューから全文を再処理・Finderで表示・ゴミ箱に移動ができます。全文の再処理では元の認識結果・議事録を会議フォルダの `meeting.before-reprocess.json` にバックアップします。ゴミ箱への移動は確認のうえ会議フォルダごと行い、録音中・処理中の会議は移動できません。

議事録とMarkdown書き出しの最後に「アクションアイテム」を一覧化します。Markdownは会議タイトルを唯一の見出し1とし、ファイル名の初期値も会議タイトルです。タスクID・作業・担当者・期限・根拠発言ID・完了/撤回状態を構造データとして保存します。更新で省略されたタスクや担当者・期限は保持します。AIの応答は項目ごとに検証し、存在しない根拠IDを含む項目や今回の新しい発言を根拠に含まない項目はその項目だけを採用せず、除外件数を画面に表示します。原文にない担当者・期限は採用せず「未定」とします。AIによる意味の解釈は原文で確認してください。

## 処理方式

音声は録音中から約12秒ごとにOpenAIの音声認識API（`gpt-4o-transcribe`）へ送信し、文字起こしをResponses APIへ送って議事録を生成します。無音のチャンクは送信しません。API利用料が発生します。以前のバージョンにあったMac内認識（Apple Speech）とOllamaによる要約は廃止しました。それらの方式で録った会議も、残りの処理や再処理はOpenAIで行います。以前のキーワード抽出で作った議事録は、そのことを表示したうえでそのまま読めます。

## 保存と制限

保存先は既定で「書類」フォルダの `キロクル`（`~/Documents/キロクル`）です。設定の「保存先」で変更でき、変更するとこれまでの会議フォルダも移動します（録音中・処理中は変更できません）。初めて書類フォルダへ保存するときは、macOSがアクセスの許可を求めます。書類フォルダをiCloud Driveと同期している場合は、録音もアップロードされます。以前のバージョンが `~/Library/Application Support/Minutes/Meetings/` に保存した会議は、起動時に新しい保存先へ移動します。

会議ごとに「2026-10-03 17.26 週次定例」のような日付とタイトルのフォルダを作り、次のファイルをまとめて保存します。

- `議事録.md`：議事録と文字起こし。内容が変わるたびにアプリが書き直すので、手を加えるときは別名で保存してください。
- `録音.m4a`：Mac音声とマイクを共通の時刻で重ねた聞き返し用の音声。録音を停止すると作成します。
- アプリが使うデータ：元音声（`system.caf`・`microphone.caf`）・12秒前後のチャンク・共通時刻の `recording.json`・会議の `meeting.json`。会議JSONには、チャンクごとの未処理/処理中/完了/失敗、試行回数、再試行時刻、認識結果、議事録、処理済み発言IDをまとめて原子的に保存します。JSONの保存はUIとは別のactorで処理します。文字起こしの進捗は1秒以上まとめて書き込み、大きな会議では書き込み量を毎秒約50KB（最大10秒間隔）に抑えます。録音の開始・停止・再処理・要約の更新・終了時は即時に保存します。APIキーは会議JSONへ保存しません。

文字起こしは全会議で最大2件を同時実行します。会議間で順番を回し、録音を続けながら以前の会議も処理します。一時的なネットワーク障害・HTTP 429/5xxは間隔を空けて最大3回試行し、サーバーが `Retry-After` を返した場合はその時間（最大2分）待ちます。認証などのエラーは自動再試行しません。上限に達した失敗は画面に残り、手動で再開できます。エラー表示にはAPIが返した説明を含めます（APIキーらしき文字列は伏せ字にします）。

通常終了時は録音の末尾と、前回の保存以降に変更のあった会議の処理状態を保存し、AIの完了を待たずに終了します。再起動時は未処理・中断済みの仕事を復旧し、完了済みのチャンクは再送しません。完了済みの会議は復旧の対象にせず、書き直しもしません。強制終了・電源断の直前に完了したチャンクは、未保存のため再処理する場合があります。復旧には保存したAPIキーが必要で、API利用料が発生する場合があります。キーがない場合は設定後に「未処理を再開」を押してください。録音自体は自動再開しません。

録音中はアイドルによるシステムスリープを抑制します。手動スリープ・録音中のマイクの切断・15秒以上のマイク入力途絶は中断として扱い、保存済み音声を保持して停止します。カメラや使っていないマイクの切断では録音を止めません。入力機器や音声形式の変更では既存音声を上書きせず新しいファイルへ分割します。スリープ・機器切断後は入力を確認して録音を開始してください。強制終了・電源断では書き込み中の最後のチャンクを復旧できない場合があります。

ヘッドホンを推奨します。スピーカー音がマイクに入る場合、二重収録が起きます。議事録へ渡す際に、2秒以内に両トラックで同じ長めの文が認識された場合は根拠IDを保持してまとめます。これは重複候補の抑制であり、音声のエコー除去ではありません。認識文が異なる場合の重複や会議内の話者分離には未対応です。「Mac音声」「マイク」は収録元であって話者識別ではありません。通知音なども入ります。保護された音声・すべての外部オーディオ機器の収録は保証しません。

逐次処理の時刻は共通のキャプチャ時刻を基準にしたチャンク開始位置。クラウド時刻は単語ごとの精密時刻ではありません。新しい録音は再処理にも同じチャンク時刻を使い、トラック開始のずれや収録の間隔を維持します。時刻データのない旧録音は各トラック内の経過時刻になります。チャンク境界で単語が分かれる場合があります。認識やAPIが遅い場合は未処理の音声が増え、表示に遅れが出ます。30秒は更新要求の間隔であり、生成完了まで30秒を保証するものではありません。要約の新規入力は1回最大20発言・通常12,000文字以内に分割し、処理済みIDで重複送信を防ぎます。既存の議事録も送信するため、タスクや決定事項が非常に多い会議ではモデルの入力上限に達する可能性があります。

アプリはローカル開発用の署名です（既定はad-hoc）。配布用のDeveloper ID署名・公証は未対応です。会議中の双方向音声と権限ダイアログは実機での確認が必要です。

## 要約API

議事録は [OpenAIのStructured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) の `text.format` にJSON Schemaを指定して差分項目を取得します。応答の形式に加え、アプリ側で根拠発言ID・担当者・期限を検証します。生成の拒否や未完了応答は以前の議事録を置き換えません。

## 自動チェック

```sh
./scripts/check.sh   # 整形チェック → SwiftLint → 回帰テスト → リリースビルド
./scripts/format.sh  # Swiftコードを自動整形
./scripts/lint.sh    # 整形チェックとSwiftLintのみ
```

`check.sh` と `lint.sh` はソースを変更せず、違反やテスト失敗があればその場で終了します。必要なツールがない場合もチェックを省略せずエラーにします。`build.sh` からも同じチェックを必ず実行します。これはローカルのビルド手順に組み込んだチェックです。GitHub ActionsやGitフックは未設定です。

整形は [swift-format](https://github.com/swiftlang/swift-format) に統一し、`.swift-format` で4スペース・120文字を基本とします。長い文字列リテラルは分割せず、複数行のAIプロンプトも再折り返ししません。`.editorconfig` にもインデントと改行の設定を記載しています。

[SwiftLint](https://github.com/realm/SwiftLint) は `.swiftlint.yml` で25ルールを指定し、強制キャスト・`try!`・変数の強制アンラップ、重複条件・辞書キー、通知監視の破棄、SwiftUI状態のアクセス範囲などをチェックします。整形ルールはswift-formatが担当し、SwiftLintの警告もエラーとして扱います。固定のURL文字列に対する `URL(string:)!` はSwiftLintの既定の例外です。ソース・テスト・`Package.swift` を対象とし、生成物は除外します。

この環境ではSwift 6.4・SwiftLint 0.65.1で検証しています。`lint.sh` は `xcrun` で選ばれたSwiftコンパイラのツールチェーンをSwiftLintにも指定し、Command Line Tools環境でSourceKitを読み込めるようにしています。ツールを更新した場合は、整形差分を確認して `check.sh` を再実行してください。

## 回帰テスト

```sh
./scripts/test.sh
```

31件の回帰テストで、音声分割・両トラックと停止末尾・停止失敗の分離・共通時刻・無音除外・完了状態を検証します。さらに、差分入力の上限、タスクIDと根拠の保持、根拠のない項目だけの除外と原文にない担当者・期限の破棄、旧形式の互換性、構造化API応答と拒否、同時実行数、再試行上限、失敗分の再処理、再起動からの復旧、次会議への分離、通常終了時の保存、古い保存内容による上書き防止、音声形式の変更、入力途絶検知、更新要求の集約、全文再処理のバックアップ、一部チャンク欠落時の復旧を確認します。加えて、旧キーワード抽出の議事録の表示、録音を止めるべき機器切断の判定、要約失敗後の再試行、APIエラー説明と `Retry-After`、保存の集約と未変更の会議の非書き込み、完了済み会議の復旧除外、書き出しの見出しとファイル名、会議の削除、会議フォルダの名前と議事録ファイル、両トラックを時刻どおりに重ねた録音ファイル、保存先の変更に伴う移動、以前の保存場所からの移動を確認します。

認識/APIの境界は模擬応答を使用し、実音声の送信や権限変更は行いません。模擬していない通信はテスト中すべて失敗させ、実APIへは送信しません。長時間の実会議、実際の日本語認識精度、OSのスリープ通知・デバイス切断、OpenAIの実通信は別途実機検証が必要です。

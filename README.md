# キロクル

macOS 15以降向けのSwiftUIアプリ。会議アプリを使いながらMacの出力音声とマイクを録音し、文字起こし・議事録を逐次更新します。

## 起動

開発時はSwift 6以降のCommand Line Tools（またはXcode）とSwiftLintが必要です。SwiftLintは初回にインストールしてください。

```sh
brew install swiftlint
```

```sh
./scripts/build.sh
open dist/キロクル.app
```

`build.sh` は整形チェック・静的チェック・回帰テストに成功してから、リリースビルドとアプリの作成を行います。

初回はマイク・画面とシステムオーディオ録音の権限を許可してください。必要に応じてアプリを終了・再起動してください。ローカル音声認識には音声認識の許可も必要です。

1. 設定でマイクを選択。クラウドを使う場合はOpenAI APIキーを保存（Keychain）。
2. 「Mac内のみ」「Mac内認識＋GPT要約」「クラウドAI」を選択して録音を開始。
3. Zoom/Teams等で通常どおり会議に参加。音声ルーティングや会議側のマイク設定を変更する処理はありません。
4. 約12秒ごとの音声チャンクを文字起こしし、30秒ごとに既存の議事録と新しい発言から差分更新します。前の要約が処理中なら更新要求をまとめ、完了後に最新の発言を反映します。画面に議事録の更新時刻と未処理・失敗件数を表示します。
5. 停止すると音声ファイルを閉じ、残りはバックグラウンドで処理します。次の会議の録音を開始できます。会議ごとの処理方式は録音開始時に固定し、後の設定変更が前の会議へ混ざらないようにします。
6. 失敗した会議は「未処理を再開」で未完了の音声だけ再実行できます。処理方式を変更してやり直す場合は「再処理」メニューから全文を再処理します。元の認識結果・議事録は会議フォルダの `meeting.before-reprocess.json` にバックアップします。

議事録とMarkdown書き出しの最後に「アクションアイテム」を一覧化します。タスクID・作業・担当者・期限・根拠発言ID・完了/撤回状態を構造データとして保存します。更新で省略されたタスクや担当者・期限は保持します。存在しない根拠ID、原文にない担当者・期限を含む応答は採用せず、以前の議事録を保持します。AIによる意味の解釈は原文で確認してください。発言抽出モードは原文の候補を表示し、担当者・期限を不明とします。

## 処理方式

- Mac内のみ：Apple Speechの日本語端末内認識。対応状況を確認し、非対応ならエラーにします。クラウドへのフォールバックはありません。議事録は既定でキーワードに基づく発言抽出です。設定でMac内AIモデル名を指定すると、起動済みOllamaの `http://127.0.0.1:11434/api/chat` を使って意味要約できます。Ollamaとモデルは別途用意してください。モデル情報に外部ホストが指定されているモデルとHTTPリダイレクトは拒否します。モデル未指定時の抽出はLLM要約ではありません。
- Mac内認識＋GPT要約（既定）：文字起こしはAppleの端末内認識、要約はOpenAIの `gpt-6-sol`。音声は送信せず、認識済みテキストを送信します。Ollamaは不要。APIキーが必要で、API利用料が発生します。
- クラウドAI：録音開始と同時に音声チャンクをOpenAIの音声認識APIへ送信。文字起こしをResponses APIへ送って議事録を生成します。音声認識は `gpt-4o-transcribe`、議事録の初期設定は `gpt-6-sol`。後者は設定で変更できます。API利用料が発生します。

## 保存と制限

`~/Library/Application Support/Minutes/Meetings/<UUID>/` に元音声・12秒前後のチャンク・共通時刻の `recording.json`・会議の `meeting.json` を保存します。会議JSONには、チャンクごとの未処理/処理中/完了/失敗、試行回数、再試行時刻、認識結果、議事録、処理済み発言IDをまとめて原子的に保存します。JSONの保存はUIとは別のactorで処理します。APIキーは会議JSONへ保存しません。

文字起こしは全会議で最大2件、Appleの端末内認識は最大1件を同時実行します。会議間で順番を回し、録音を続けながら以前の会議も処理します。一時的なネットワーク障害・HTTP 429/5xxは間隔を空けて最大3回試行し、認証などのエラーは自動再試行しません。上限に達した失敗は画面に残り、手動で再開できます。

通常終了時は録音の末尾と処理状態を保存し、AIの完了を待たずに終了します。再起動時は保存した会議の処理方式で未処理・中断済みの仕事を復旧し、完了済みのチャンクは再送しません。クラウド方式は保存したAPIキーが必要で、復旧によるAPI利用料が発生する場合があります。キーがない場合は設定後に「未処理を再開」を押してください。録音自体は自動再開しません。

録音中はアイドルによるシステムスリープを抑制します。手動スリープ・マイク切断・15秒以上のマイク入力途絶は中断として扱い、保存済み音声を保持して停止します。入力機器や音声形式の変更では既存音声を上書きせず新しいファイルへ分割します。スリープ・機器切断後は入力を確認して録音を開始してください。強制終了・電源断では書き込み中の最後のチャンクを復旧できない場合があります。

ヘッドホンを推奨します。スピーカー音がマイクに入る場合、二重収録が起きます。議事録へ渡す際に、2秒以内に両トラックで同じ長めの文が認識された場合は根拠IDを保持してまとめます。これは重複候補の抑制であり、音声のエコー除去ではありません。認識文が異なる場合の重複や会議内の話者分離には未対応です。「Mac音声」「マイク」は収録元であって話者識別ではありません。通知音なども入ります。保護された音声・すべての外部オーディオ機器の収録は保証しません。

逐次処理の時刻は共通のキャプチャ時刻を基準にしたチャンク開始位置。クラウド時刻は単語ごとの精密時刻ではありません。新しい録音は再処理にも同じチャンク時刻を使い、トラック開始のずれや収録の間隔を維持します。時刻データのない旧録音は各トラック内の経過時刻になります。チャンク境界で単語が分かれる場合があります。認識やAPIが遅い場合は未処理の音声が増え、表示に遅れが出ます。30秒は更新要求の間隔であり、生成完了まで30秒を保証するものではありません。要約の新規入力は1回最大20発言・通常12,000文字以内に分割し、処理済みIDで重複送信を防ぎます。既存の議事録も送信するため、タスクや決定事項が非常に多い会議ではモデルの入力上限に達する可能性があります。

アプリはローカル開発用のad-hoc署名です。配布用のDeveloper ID署名・公証は未対応。APIキー未設定でクラウドの実API検証は行っていません。会議中の双方向音声と権限ダイアログは実機での確認が必要です。

## 要約API

クラウド要約は [OpenAIのStructured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) の `text.format` にJSON Schemaを指定して差分項目を取得します。Ollamaでは [公式の構造化出力](https://docs.ollama.com/capabilities/structured-outputs) の `format` を使用します。応答の形式に加え、アプリ側で根拠発言ID・担当者・期限を検証します。生成の拒否や未完了応答は以前の議事録を置き換えません。

## 自動チェック

```sh
./scripts/check.sh   # 整形チェック → SwiftLint → 回帰テスト → リリースビルド
./scripts/format.sh  # Swiftコードを自動整形
./scripts/lint.sh    # 整形チェックとSwiftLintのみ
```

`check.sh` と `lint.sh` はソースを変更せず、違反やテスト失敗があればその場で終了します。必要なツールがない場合もチェックを省略せずエラーにします。`build.sh` からも同じチェックを必ず実行します。これはローカルのビルド手順に組み込んだチェックです。GitHub ActionsやGitフックは未設定です。

整形は [swift-format](https://github.com/swiftlang/swift-format) に統一し、`.swift-format` で4スペース・120文字を基本とします。長い文字列リテラルは分割せず、複数行のAIプロンプトも再折り返ししません。`.editorconfig` にもインデントと改行の設定を記載しています。

[SwiftLint](https://github.com/realm/SwiftLint) は `.swiftlint.yml` で25ルールを指定し、強制キャスト・`try!`・変数の強制アンラップ、重複条件・辞書キー、通知監視の破棄、SwiftUI状態のアクセス範囲などをチェックします。整形ルールはswift-formatが担当し、SwiftLintの警告もエラーとして扱います。固定のURL文字列に対する `URL(string:)!` はSwiftLintの既定の例外です。ソース・テスト・`Package.swift` を対象とし、生成物は除外します。

この環境ではSwift 6.4・SwiftLint 0.65.1で検証しています。`lint.sh` は `xcrun` で選ばれたSwiftコンパイラのツールチェーンをSwiftLintにも指定し、Command Line Tools環境でSourceKitを読み込めるようにしています。ツールを更新した場合は、整形差分を確認して `check.sh` を再実行してください。

## 回帰テスト

```sh
./scripts/test.sh
```

21件の回帰テストで、音声分割・両トラックと停止末尾・停止失敗の分離・共通時刻・無音除外・完了状態を検証します。さらに、差分入力の上限、タスクIDと根拠の保持、不正な担当者の拒否、旧形式の互換性、構造化API応答と拒否、同時実行数、再試行上限、失敗分の再処理、再起動からの復旧、次会議への分離、通常終了時の保存、古い保存内容による上書き防止、音声形式の変更、入力途絶検知、更新要求の集約、全文再処理のバックアップ、一部チャンク欠落時の復旧を確認します。

認識/APIの境界は模擬応答を使用し、実音声の送信や権限変更は行いません。長時間の実会議、実際の日本語認識精度、OSのスリープ通知・デバイス切断、OpenAI/Ollamaの実通信は別途実機検証が必要です。
